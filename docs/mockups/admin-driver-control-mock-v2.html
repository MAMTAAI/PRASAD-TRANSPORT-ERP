What the admin gets, without leaving the screen

  • Three ways in. ① a Driver Command Center row, ② the driver's name in the dispatch chat header, ③ the truck pin on Live Fleet Map or its trip row. The dashboard stays behind, dimmed; Esc or ✕ brings it back untouched.
  • Status & profile: Suspend asks for one reason chip, blocks login and kills the phone session; Re-activate is one click. Profile Edit → Save / Cancel in place; document-approved numbers locked; Delete = archive with typed confirmation.
  • Live tracking: mini-map with the truck on its route, ping age, speed, km left, ETA, jump to the big map.
  • Digital Locker: every paper with source, OCR reading, Milan score and status. Approve writes to core. Resend / Reject picks a reason and pushes it to the driver. Ask driver requests a paper never sent.
  • Ledger issuance (new): HSD and cash for the open trip. Target, issued, balance for each; a two-field form to issue HSD (litres, pump, slip) or pay cash (amount, mode, ref). The moment you press Issue, the balance recalculates, goes red if over target, a khata line and voucher are written, and the "Driver sees" card shows exactly what the driver's phone now shows.

What already exists in the code (verified 3-Sep; reuse, not rebuild)

  • Drawer shell: the Approval Drawer is the ERP's only right-side slide-out; the new panel copies its shell. "Open from anywhere" uses the same window event the drill-down drawer already uses.
  • Entry ① Driver Command Center rows carry id, name, mobile. Entry ② dispatch trip-chat rows carry driver id and phone. Entry ③ the tracking feed carries the driver's name only, so one field (driver id) is added server-side.
  • Suspend / Re-activate / Delete = Access Control Hub block / activate / archive, admin-only, written to access_hub_audit; block also deletes the phone's sessions.
  • Locker = the partner-documents queue filtered to one driver; approve runs applyToCore (DL, Aadhaar, bank) and WhatsApps the driver; reject sets NEEDS CORRECTION and WhatsApps "dobara bhejein". PAN and HZD are not document types yet.
  • Ledger: the driver khata and its ledger route exist, and a pay route exists for driver requests. Issue HSD / Pay cash from this panel = one new route that writes the khata line plus the voucher and stamps the trip; the driver app reads the same khata. Targets need two columns on the route master (km-per-litre, cash allowance).
  • Live position keyed by driver exists only while the driver is logged in on an IN_TRANSIT trip; otherwise the trip's last GPS ping; otherwise "no live fix".
