Gate 1 rules

  • Who: office staff, admins, super-admins. Desktop first; it works on a laptop in the office or at home.
  • How: username + password, then the one-time code (WhatsApp and email) that is already live for staff since 31-Aug. The mock shows the same two steps.
  • Where it lands: Command Center: Transport Fleet Ops, always. No role picker, no portal chooser.
  • Who is refused: any driver, vendor, customer or fleet partner. They have no password at all, so there is nothing to guess. The screen tells them to use the mobile app.
  • Session: a staff token. It can open the external portals only through the read-only "View as" preview that exists today. It never becomes a driver session.
  • What changes on screen: today's login page carries Customer / Partner / Driver buttons beside the staff form. In this design those buttons leave the desktop door entirely; externals only ever see Gate 2.

📌 Upon OTP verification, the backend auto-routes the user directly to their isolated mobile portal (e.g., Driver App). They never see the Admin dashboard.
The phone never asks "who are you". The server already knows the number: it is on exactly one master (driver, vendor, customer or fleet partner), and that decides the portal. Nothing to pick, nothing to get wrong.

Gate 2 rules

  • One field. Mobile number. No username, no password, no role, no form. Big button, Hindi first.
  • OTP comes on WhatsApp, falls back to SMS. The app reads it itself when it can. Test numbers use the dev bypass that is already on the box.
  • Routing is server-side. The number is looked up on the masters; the session is issued with that one role; the phone downloads only that portal's code (the Super-App shell already splits the five portals into separate chunks).
  • Unknown number: the OTP still verifies, but no portal opens. The screen says to get registered by the office, with a call button.
  • Confinement: an external session can only call its own /portal/… routes (the API guard returns 403 elsewhere), and its writes land in the pending queues, never straight into the books.
